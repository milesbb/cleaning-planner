# Room — Claude Context

The screen's notes; the rules for every screen are in `apps/web/CLAUDE.md`.

Room (`/room?id=`): the room's jobs soonest first with how often, who and next due, from `lib/home/room-jobs.ts` (`summariseRooms`, `jobsInRoom`) and `useRoomSources` (rooms, jobs, `GET …/progress`, people). Repeat-after-done jobs show a calm freshness bar (`freshnessOfJob` in `room-freshness.ts`, from `freshness` in `@cleaning-planner/schedule`: full when just done, empty on the due day, never red), read out as "Fresh for about 4 more days" or "Ready for a clean"; jobs on set days have none. **Edit room** (header, `EditRoomSheet`): rename and appliances (`RoomDetailsForm`, keyed by the room's version; the appliances on offer come from `lib/jobs/appliances.ts`, which a test keeps the same as the job library; ticking one adds its usual jobs and unticking one removes them, done by the API; sends only what changed with the version it read, no automatic retry; a version conflict offers Reload, which refreshes the home and starts again from the saved name) and **Remove room** in the same sheet, which asks first with how many jobs go with it (`removalWarning`), then goes back to Home. The mutations are in `use-room-actions.ts`. The sheet loads on first tap (`EditRoomButton`, `LazySheet`); `RoomNotFound` lives in `room-not-found.tsx` so Add a job can show it without loading Room's sheets.
